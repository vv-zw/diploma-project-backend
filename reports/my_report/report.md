# 推荐系统实现说明

## 当前实现概览

当前项目已经从早期的同步刷新推荐，升级为以下实现：

- 主推荐链路：`NCF + TextCNN + 规则特征融合`
- 刷新机制：`异步刷新任务 + 状态轮询 + 刷新完成后读取缓存`
- 用户偏好管理：`movie` 与 `series` 分桶存储、分桶计算权重

当前最终排序分数采用如下融合策略：

```text
final_score =
0.35 * ncf_score +
0.30 * textcnn_score +
0.20 * genre_score +
0.10 * quality_score +
0.05 * diversity_score
```

同时保留：

- 负反馈惩罚
- 黑名单过滤
- 多样性重排

## 推荐链路

### 1. 电影与剧集分桶偏好

用户偏好不再使用一份全局权重，而是拆分为两类：

- `preferences.movie`
- `preferences.series`

对应的权重也分别维护：

- `count_weights.movie`
- `count_weights.series`

这样可以保证：

- 电影推荐只根据电影偏好计算
- 剧集推荐只根据剧集偏好计算

避免了“剧集推荐错误复用电影权重”的问题。

### 2. 主推荐流程

以任意内容类型 `type=movie|series` 为例，推荐生成流程如下：

1. 读取对应数据集
2. 读取该类型下的用户偏好与行为数据
3. 尝试训练并生成 `NCF` 分数
4. 尝试使用 `TextCNN` 生成文本语义相似度分数
5. 计算规则特征分数
6. 对所有候选项按融合分值排序
7. 应用多样性重排
8. 将结果写入缓存 JSON

### 3. 降级策略

当前实现保留了分层降级：

1. 理想链路  
   `NCF + TextCNN + 规则分`

2. `TextCNN` 不可用  
   `NCF + 规则内容相似度 + 规则分`

3. `NCF` 不可用  
   `TextCNN + 规则分`

4. 两者都不可用  
   `规则内容推荐 + 多样性重排`

## 异步刷新机制

### 改造前

早期实现中：

- `GET /get_recommend` 在带 `refresh=true` 时会同步重新生成推荐
- 前端刷新按钮会一直等待模型运行完成
- 在 `NCF + TextCNN` 启用后，刷新耗时增加，容易出现前端超时

### 改造后

现在接口职责已经拆分：

#### 1. `GET /get_recommend`

作用：

- 只读取当前缓存推荐结果
- 不做模型训练
- 快速返回

#### 2. `POST /refresh-recommendations`

作用：

- 只负责创建后台刷新任务
- 立即返回 `job_id`

返回示例：

```json
{
  "code": 0,
  "message": "refresh_queued",
  "type": "movie",
  "job_id": "movie_20260313_154500_ab12cd34",
  "status": "queued"
}
```

#### 3. `GET /refresh-status`

作用：

- 根据 `job_id` 轮询刷新状态

状态包括：

- `queued`
- `running`
- `done`
- `failed`

### 前端刷新流程

电影页与剧集页均已统一为以下逻辑：

1. 用户点击“刷新”
2. 前端调用 `POST /refresh-recommendations`
3. 获得 `job_id`
4. 页面显示“正在刷新推荐，请稍候...”
5. 前端轮询 `GET /refresh-status`
6. 当状态变为 `done` 时，再调用 `GET /get_recommend`
7. 当前页直接刷新列表内容

因此现在的刷新体验是：

- 不再同步卡住等待模型运行
- 刷新完成后当前页立即更新
- 不需要退出页面再重新进入

## 规则特征说明

除深度模型外，系统仍保留规则特征用于稳定排序和增强可解释性：

- `genre_score`：类型偏好匹配分
- `quality_score`：由评分与年份构成的质量分
- `diversity_score`：用于鼓励推荐结果不过度集中
- `negative_feedback_penalty`：对不感兴趣项目进行惩罚

## 当前离线评估结论

基于当前报告样本，已有离线结果表明：

- `ncf_hybrid` 相比纯内容推荐在 `Precision@20`、`HitRate@20`、`NDCG@20` 上更优
- 当前项目已经进一步演进为主链路 `NCF + TextCNN + 规则融合`
- 后续建议继续补充剧集偏好样本，并将新的主链路纳入 `compare.py` 做独立评估
